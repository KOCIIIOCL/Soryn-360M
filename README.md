# Soryn-360M (Soric-360M)

[English](README.en.md) | Русский

SmolLM2-360M-Instruct, дообученная под вызов инструментов, математику и русский язык.

Веса в репо - GGUF Q8_0, можно запускать сразу через llama.cpp, Ollama или любой
другой движок. Для работы ничего собирать не надо.

## Что внутри

- Базовая модель: HuggingFaceTB/SmolLM2-360M-Instruct (360M параметров)
- Формат: GGUF, квантование Q8_0
- Файл: `soryn-360m-q8_0.gguf` (368 МБ)

Скачать веса можно из [Releases](https://github.com/KOCIIIOCL/Soryn-360M/releases/tag/v1.0).
В самом репозитории лежат только README и Modelfile, веса отдельным файлом.

Полный файн-тюнинг, не LoRA. Обучалась на 4 ГБ VRAM через bf16 + 8-bit AdamW
и gradient checkpointing, так что для самой модели железо нужно скромное.

## Как запустить

Самый простой вариант - через llama.cpp:

```bash
llama-cli -m soryn-360m-q8_0.gguf -sys "You are a helpful assistant." -p "What is 17 times 23?"
```

Или через сервер:

```bash
llama-server -m soryn-360m-q8_0.gguf --port 8080
```

Потом обычный OpenAI-совместимый API на localhost:8080.

Через Ollama тоже работает, модель просто кидается в папку models.

## Бенчмарки

Сравнение с обычной SmolLM2-360M-Instruct (тоже Q8_0), обе гонялись на одинаковых
вопросах, температура 0.

### Вызов инструментов (canonical system prompt, 5 вопросов)

| Метрика | SmolLM2-360M-Instruct | Soryn-360M (Soric-360M) |
|---|---|---|
| Валидный JSON | 4/5 (80%) | **5/5 (100%)** |
| Правильное имя функции | 3/5 (60%) | **5/5 (100%)** |
| Правильные аргументы | 2/5 (40%) | **5/5 (100%)** |

Базовая модель на половине вопросов вообще не понимает, что от неё хотят: то
копирует описание функции из системного промпта вместо вызова, то вставляет
заглушку `{"name": "function_name", "arguments": {"arg": "value"}}` из примера.
Soryn-360M вызывает нужный инструмент с первого раза.

### Арифметика (12 вопросов)

| Метрика | SmolLM2-360M-Instruct | Soryn-360M (Soric-360M) |
|---|---|---|
| Правильных ответов | 8/12 (67%) | 8/12 (67%) |

Тут паритет. Обе модели знают таблицу умножения и хорошо считают в пределах
тысячи, но обе же и ошибаются на 99x99 и 1234+5678. 360M параметров физически
не хватает, чтобы держать в голове многозначные операции.

### Арифметика на русском (5 вопросов)

| Метрика | SmolLM2-360M-Instruct | Soryn-360M (Soric-360M) |
|---|---|---|
| Правильных ответов | 2/5 (40%) | **4/5 (80%)** |

Базовая модель на русском вообще не отвечает на вопрос: начинает повторять
его обратно и рассуждать про "почему 25 умножить на 4 работает не так".
Soryn-360M понимает задачу и решает её.

### Русский чат

По качеству ответов на свободные вопросы на русском обе модели примерно
одинаково слабые. Это всё ещё 360M, чат на уровне "ответ есть, но местами
бред". Основной прирост от файн-тюна - именно в инструкциях и вызове
инструментов, а не в разговоре.

## Ограничения

- Модель маленькая. Сложная математика, длинные рассуждения и качественный
  чат остаются за её пределами.
- Русский язык понимает заметно лучше базы, но генерация всё равно часто
  скатывается в галлюцинации.
- Лучший результат даёт явный системный промпт. Без него может начать
  повторять вопрос пользователя.
